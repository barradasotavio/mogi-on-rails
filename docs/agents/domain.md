# Domain docs

One domain context: `GLOSSARY.md` at the repository root and ADRs in `docs/adr/`.

- Before exploring an area, read the glossary and the ADRs for that area.
- Use glossary terms consistently in code, issues and explanations, and surface contradictions with the glossary or an ADR.
- Resolve terminology with the domain-modeling skill; the glossary holds domain definitions only.
- Create an ADR only for an agreed decision with a real trade-off that is costly to reverse and surprising without context. Write a document once its content is resolved.
