# Design system contract

Screens follow the [mogi experience contract](experience.md). Visual detail follows Apple's HIG and Liquid Glass ([research](../research/hig-liquid-glass.md)). The source of truth is this contract plus what ships on `main`, in this order:

1. **Components**: the internal layer in `apps/web/components/ui`. Each component's anatomy, sizes and states live in its doc comment; read the component before using or changing it.
2. **Tokens**: `apps/web/design-system/preset.json`, `apps/web/design-system/product-tokens.json` and their CSS in `apps/web/app/globals.css` ([preset and component layers](#preset-and-component-layers)).
3. **Screens**: the composed screens in `apps/web/components` settle any detail the contract and the components leave open; a new screen matches its nearest existing one.

When code and this contract disagree, the contract wins; a change that means to move the design updates this contract in the same change.

## Preset and component layers

- `apps/web/design-system/preset.json` is the reviewed source of truth for component configuration and CSS tokens. It records the shadcn Create preset (Radix base, Vega style, emerald theme, code `bImeAgi`) and the pinned CLI that generated it; its URL opens the same configuration. Theme tokens are its generated values. Changing the preset is a design decision: regenerate components and tokens only with that CLI and configuration, inspect the diff, update this contract in the same change.
- Generated originals live in `vendor/shadcn/ui`, produced by the pinned CLI with the existing aliases and kept exactly as generated; product behavior goes in the wrappers. Shared compositions live in `components/ui` (the **internal layer**); app screens use only these wrappers.
- Product tokens (`design-system/product-tokens.json`) only add to the preset; preset tokens keep their generated values. `--rule` is the opaque divider for tables, lists and the exported image, because the translucent dark-mode border vanishes over the background and brightens over a highlighted column. Team colors exist only as `--team-1` … `--team-6` (six: 2v2 has six teams). FFA players take `--player-1` … `--player-12` by bot list order: the six team colors, then six more.
- **Tint.** Emerald is the primary, the app's tint, and the icon's color (`#007a55`, the light primary). Fills use `primary`; tint as ink (links, symbols, checks, radios, the current sidebar row) uses `--link`, the light primary and a lighter emerald in dark, where the primary is too dark to read on the background. Green that carries meaning (movement and value gain, team 4) is shadcn green, so it reads apart from the tint; gain as text uses `--movement-up-foreground` (green-700 in light, for AA), and bars and marks keep `--movement-up`.
- Inter is self-hosted ([offline](offline.md)); third-party licenses ship through `prepare:ocr`.
- iOS installed-app viewport (omits `apple-mobile-web-app-capable`, appends `viewport-fit=cover` after `load`): the why is in `app/layout.tsx` and `tests/opening.production.spec.ts`.

## Design checks

`npm run lint` runs ESLint (`eslint.config.mjs`, including the mandatory shadcn rules of `@shadcn/lint`) and `check:design` (`scripts/check-design-system.ts`, cases in `npm run test:design`). Each rejection names the broken rule; where a replacement component exists, the message names it too. Browser tests and visual review cover what the checks can't see: structural HTML versus a hand-built Card or Item, and visual quality.

- **Outside the internal layer**, a visible control, material, divider, clipboard write, measured bar, native alert or fullscreen dialog is built from the internal layer's component. A new control enters the internal layer first.
- **Everywhere**: tokens in `app/globals.css` match the preset; CSS imports stay the reviewed list (a new stylesheet extends this contract first, so overrides can't hide in it); decisions use an alert or a sheet ([notices](#notices)); command labels are Title Case ([rule](copy.md#capitalization)).
- **Native elements allowed** outside the internal layer: hidden and hidden-value inputs, upload pickers, and native buttons composed directly under `Item asChild` or `DialogTrigger asChild` (they keep the component's interaction or are invisible), plus structural HTML.
- **Lint layers.** ESLint relaxes the variant and class-expression rules (`no-restyle`, `no-arbitrary-values`, `require-static-classes`) for the generated originals; wrappers keep them, except for the per-file allowances below. Raw colors, inline styles and unknown classes are errors in both layers.
- **Lint allowances** for raw sizes or classes in a wrapper are per file in `eslint.config.mjs` (the surfaces `sheet` and `sidebar-overlay` compose Radix and Vaul directly, so `no-restyle` is off for them). A new allowance needs a product reason in its comment.

## Size classes

| Class | Viewport | Shape |
| --- | --- | --- |
| compact | below 768px | one column; surfaces are bottom sheets; controls float at the bottom |
| regular | 768px and up | toolbar at the top ([chrome](#desktop-chrome)); surfaces are a floating inspector or a centered modal |

- Only these two classes; `components/ui/size-class.tsx` is the only script source of the breakpoints. The 1280px sidebar docking ([experience](experience.md#regular-navigation)) is a visibility rule within regular.
- First paint is decided in CSS (`md:` / `xl:` and container queries). Script reads the size class only to choose a surface when it opens.
- Content inside a column adapts with container queries, so what sits behind an opening surface keeps its layout.

## Materials

- Glass belongs to the control layer only: toolbars, floating bars, corner buttons, the medium sheet, toasts and blocking alerts. Content (lists, tables, text) sits on opaque surfaces. `glass` (neutral) and `glass-tint` (primary) are the glass materials, plus the regular toolbar, whose `toolbar` utility turns to glass as content scrolls under it; all three live in `app/globals.css` and turn opaque under reduced transparency.
- **No scrim under glass** ([why](../research/hig-liquid-glass.md#what-apple-says-and-the-rule-that-came-out-of-it)). Glass samples what is behind it, so a dim there turns it muddy. The medium sheet has a clear overlay, which still closes it on an outside tap; `BlockingAlert` dims around itself (`glass-scrim`). Opaque modal surfaces (large sheet, inspector, centered dialog, confirmation, floating sidebar) sit on the one `scrim`, without blur. An opaque confirmation can open over an inspector on the same scrim, so it is raised: a shadow, and in dark mode the lighter `bg-muted` fill, since dark surfaces show elevation by lightness.
- The scroll edge effect is *soft* on compact (iOS) and *hard* on regular (macOS). Soft is `edge-mask` on the scroll container itself, a mask driven purely by CSS scroll timelines, only next to floating controls: the mogi's bottom edge on compact; a sheet's header, and its bottom with a floating footer. Hard is the regular toolbar turning to glass with a hairline once content scrolls under it. Floating mogi controls render outside the masked main.

## Surfaces

`Sheet` is the only surface for details, tasks and menus ([ADR 0005](../adr/0005-adaptive-surfaces.md)). Confirmations use `ConfirmationDialog`, blocking failures `BlockingAlert`, enlarged images only `CaptureViewer`.

| Kind | compact | regular |
| --- | --- | --- |
| `detail` | large bottom sheet | floating inspector on the right, over the content, at every width |
| `modal` | large bottom sheet | centered dialog |
| `menu` | medium sheet in glass, inset from the edges | the same actions live in the toolbar; opened anyway, a centered dialog |

- The presentation is chosen when the sheet opens and kept until it closes, so drafts survive rotating or resizing.
- One sheet at a time: deeper steps are pages in the same surface (`usePageStack`, or `useSheetPage` when a component in the content owns its pages, as Edit Result does), with Back replacing Close; Escape closes from any page. Mogi Settings, Images, each image's detail and Export share one surface.
- Only the inner content scrolls; the surface root stays fixed, even as focus moves.
- **Paging** (`Sheet`'s `pager`, `components/ui/paging.ts`): a sheet that pages among siblings ([which ones](experience.md#paging)) puts Previous and Next as two chevrons in one glass capsule at the trailing end of its bar, as Mail pairs its message arrows across from Close, on both size classes; an end disables its chevron. Shortcuts: ← and → (outside text fields, sliders and radio groups), and a sideways swipe, finger or two-finger trackpad: the page follows the drag (a quarter of it past an end), turns once it passes the threshold and springs back otherwise, one page per swipe, its momentum included. The topmost sheet takes every horizontal trackpad swipe over it or over the dimmed mogi beside it, where the pointer often rests after the tap that opened it (`overscroll-behavior-x: none` plus a window wheel listener), so the first swipe pages without the pointer moving and the browser's back/forward swipe never fires; a horizontal scroller inside keeps its own scroll. Paging keeps focus where it was, slides the new page in from the side it came from and announces its title.
- Every surface animates out as well as in; reduced motion keeps fades only.
- **Sidebar** ([behavior](experience.md#regular-navigation)): floating (`SidebarOverlay`) on the `bg-popover` surface; docked (`DockedSidebar`) on the content's background, because under Window Controls Overlay the window controls above it are painted in theme-color, which is that background. Docked, it reaches the window edge with only a hairline, square and flat, and slides its width away when closed (300 ms in, 200 ms out); floating (`SidebarOverlay`), it traps focus and closes on outside tap or Escape. Switching to compact or reaching the docking threshold closes the overlay and keeps the mogi and any open task mounted.

## Desktop chrome

Regular follows the macOS 27 window (as in Notes and Shortcuts); `components/ui/toolbar.tsx` and the `toolbar` utility in `app/globals.css`.

- **Toolbar**: a 52px band across the content column, not a floating bar. The content's background at rest, glass with a hairline once content scrolls under it. No hover tone: macOS has none, and a drag region receives no pointer events. Leading: sidebar toggle, then the screen's title and subtitle. Trailing: separate glass items with symbol and label, then the one `tint` action with its label. Unavailable items stay and are dimmed (disabled), as in macOS. When width runs out ([HIG Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)), container queries on the toolbar collapse labels to symbols first (`toolbar-label`, kept as the accessible name), then move the `toolbar-overflow` items into More (…), which opens the Menu sheet; the `tint` action keeps its label. Every control in the band (toolbar and sidebar header, labeled or not) shares one height, `--toolbar-control`, and a symbol-only control is a circle of that diameter. It mounts only on regular, by script, because its title repeats the compact header's; it exists only with loaded data, so first paint is unaffected.
- **Sidebar toggle**: inside the sidebar's header while it is docked open; in the toolbar otherwise. The two never show at once. Floating, the sidebar and its veil start below the toolbar, and the toolbar's toggle stays in place, reads Hide Mogis (`aria-expanded`) and closes it, as in Notes on iPad and Mac. The sidebar header holds only its controls, with no visible title, as in Notes and Mail.
- **Window Controls Overlay** (installed app in Chromium on desktop; `display_override` in the manifest, the user switches it from the title bar). The toolbar and the sidebar header are the title bar: they clear the window controls on both sides and their background drags the window (`app-region`), controls excepted. On compact the title bar is an empty draggable strip and content starts below it.
- **Title bar band**: the browser centers its window controls in a band of fixed height (`--titlebar-height`, about 33px on macOS) that the page can't change, and paints them in one color, `theme-color`, which is the content's background in both themes. So under the overlay (`data-titlebar="overlay"` on the root, set by the head script and kept on `geometrychange`) the toolbar and sidebar header shrink to that band (`--toolbar-height`), center their controls on the window controls' line at `--toolbar-control` (as large as the band allows, 24–30px) with 18px symbols, put the subtitle beside the title and stay opaque, with only the hairline once content scrolls. The controls' top margin is what the band leaves (about 2px); centering wins over spacing because the window controls can't move. The title bar never dims, as in macOS: every `scrim` starts below the band; the band's layers (toolbar and docked sidebar header) stay above every scrim, and the docked sidebar's hairline runs through the band to the window's top, as in Notes; a blocking glass alert dims around itself instead of on a scrim, so while one is open a full-width `titlebar-strip` backs the band and draws that hairline; and while a modal is open the band's controls only drag the window, except the toolbar's sidebar toggle over the floating sidebar. This is the one exception to the 44pt target: macOS controls are for a pointer, where the HIG default is 28 × 28pt (minimum 20 × 20pt).
- Layout reads the title bar only through `--titlebar-x`, `--titlebar-width` and `--titlebar-height`, which default to `env(titlebar-area-*)`; surfaces over everything use `--safe-top`. Without the overlay (Safari, Firefox, a tab, standalone) they resolve to zero and the layout is unchanged. Playwright can't install an app or reach this display mode, and the DevTools overlay emulation draws controls without setting the `env()` values, so `mogi-sidebar.spec.ts` sets the properties to macOS geometry and the root attribute.

## Notices

Each kind of notice has one surface; product rules are in [experience](experience.md#failure-alerts).

| Kind | Surface |
| --- | --- |
| Copy confirmation | The copy control itself (`useCopy`) |
| Brief feedback with no other home (a name asked again, a deferred question, a substitution, repeated images, a missing or deleted mogi, a failed action with no surface) | Toast: informs only; its action is only Undo or Open. Backup save and restore confirm through the save or share sheet and the restored data |
| Blocking failure (storage, data changed in another window, stale data) | `BlockingAlert`: Title Case title, one sentence, exactly its listed buttons, which exclude Dismiss |
| Edit in progress | A label on its subject: the race tile and the race sheet's subtitle; Resume and Discard are commands in that sheet |
| Refused command | `ActionScope` sentence under the triggering controls, at most one |
| Undo of the action just made (screenshot removed) | The Undo control |
| Operation error inside a sheet or form | Inline destructive `Alert` next to the control: the cause and the next step, cleared when the user acts again |
| Persistent state that explains (unread rows, diverging points, participation under review) | Inline `Alert`, cleared when the state changes |
| Empty state, failure to open | `ContentUnavailable` |

Inline notices are a bare message; title, action and dismiss belong to alerts and sheets, and a decision is always an alert or a sheet.

## Controls and lists

The internal layer's components carry their own rules in their doc comments; these are the product decisions behind them.

- **One size per action.** The same action keeps the same size wherever it appears (`TileButton` on opaque surfaces, `GlassButton` floating; `tint` marks the one primary action). Symbols in the compact floating bar are 48px, the height of the glass pills beside them.
- **Lists** are iOS grouped lists (`components/ui/list.tsx`), distinct from Item: a command in a list is a row whose title takes the link or destructive color; the trail holds a chevron, value, check or one inline action, 16px (one body font size) before the chevron. A row with `span` is as tall as that many plain rows and keeps the plain inset, so its dividers meet those of plain rows beside it. A section opens with its title and spacing; rules only separate rows, so no list (or `ListRadioGroup`) has a top or bottom rule, in a sheet or on the page (the HIG plain list). In the sidebar, the current row is highlighted; in the compact list, it only marks where focus returns, because iOS deselects the row on return.
- **Sections** follow proximity, measured between visible ink (text and box edges), not CSS boxes: a title sits 16px (`--section-title-gap`) above its content and 32px (`--section-gap`, twice as far) below the content before it, so it reads with what it titles. Both are product tokens (`design-system/product-tokens.json`). `ListGroup` owns this for every titled section: the title is a 16px line, and a list right after it is pulled up, and every list pulled down, by its rows' inset to their ink (12px, or 8px for two-line and media rows), since rows are 44pt targets. Containers of sections use `section-stack` (`app/globals.css`), never one-off margins. A long scrolling page (Instructions) spaces like Apple's feature and support pages, with more room the longer the reading: `page-stack` puts its sections `--page-gap` apart (64px; 120px from a 45rem container, as apple.com does); in a sheet, the first title clears the header as if the header were the content before it (`sheet-sections`).
- **Several sections on one page** separate by spacing alone, never a divider (HIG grouped lists). Every list of content has its own title once another titled section shares the page, so it can't read as part of the one above (Players under "Teams without a tag", Storage, the race sheet). Three kinds of group stay untitled: a summary or details at the top of a page, a group of commands (Restore, a mogi's Storage page), and a group of navigation rows whose labels name their pages (Mogi Settings). A page whose one list of content stands alone leaves it untitled, since the sheet's title names it (Players with every team tagged). A title never repeats its only row, and a section with nothing to show is hidden rather than holding a "None yet" row.
- **Self-explanatory** ([copy](copy.md#self-explanatory)): a row is a label and a trailing value; a measure is named once, in a column heading or the section title, so values line up under it. Hierarchy comes from weight, size and colour, not from more words.
- **Single choice** is `ListRadioGroup` in lists, `ChoiceGrid` / `ChoiceChips` elsewhere; choosing the active item again keeps it, since these choices are required.
- **On or off** in a list is a `Switch` (`components/ui/switch.tsx`) in the row's trail, named by the row's title, as in iOS Settings (Add Without Asking in Watched Folders).
- **Segmented control** (`components/ui/segmented-control.tsx`): switches between a few mutually exclusive views of the same content. A control, so glass, wherever it sits (toolbar or floating bar); the chosen segment is raised on the opaque background, as on iOS. Segments share the width equally from regular and fit their labels on compact.
- **Sort** (Tracks): view options, as Finder's Show View Options and Photos' sort. A glass toolbar item with the arrow-up-and-down symbol a size down (16px) and the label "Sort" at every width; it opens the `menu` sheet in sections, each with a checkmark on its current option. A choice applies at once and the panel stays open until its close button or a tap outside; an option a section's choice makes moot is disabled, not hidden.
- **Race bars** (`components/ui/race-bars.tsx`): a row's points race by race in its team's or player's colour, the last race in full colour and earlier ones lighter. Hover, or a finger dragged across, reads "Race N · P"; the strip is hidden from assistive technology, which reads the row and the table.
- **Value charts** (race bars with `domain`, and `components/ui/value-trend.tsx` for the track sheet): positions better or worse than a player's own average, as race bars diverging from a zero axis across the middle (1px in a row, 2px in the sheet), up in `--value-gain` and down in `--value-loss`, on one fixed scale (`VALUE_DOMAIN`, ±6 positions; a bar beyond it stops at the edge), never fitted per row. A track row has twelve slots for the last 12 counted races, newest at the right, so every row shares one frame; the sheet has one per race in the window (at least twelve) and the running Typical +/− as a line. Empty slots draw nothing; 0 is a neutral tick on the axis. The light pair is the movement colours; dark has its own steps, validated against the dark background and the sheet.
- **Illustrations** (`components/ui/illustration.tsx`, Instructions only): `IllustrationStage` is a box with no panel of its own that hugs its drawing's ink, so the card around it places the drawing exactly: an SVG drawing is 140px tall with its viewBox cropped to its shapes; a drawing of this app's components is 224px wide, laid out at `224 / fit` px and zoomed by `fit` (`illustration-fit`). It is hidden from assistive technology and inert, so a real component drawn inside never takes focus or a tap. Things outside the app are inline SVG drawings in the team tokens, the primary tint and the `--art-*` product tokens (`--art-device`, `--art-device-detail`, `--art-screen`, `--art-screen-row`, `--art-screen-ink`), fixed in both themes so a TV stays dark, laid out like the real screens they recall (`ResultsScreenArt`: the race scene and twelve rows on the right, the player's in gold; `PhoneAlbumArt`: the app's album on a phone, two columns of screenshots over a floating tab bar); this app is drawn with its own components. A new drawing joins that file; a new component for the page enters this layer only when an existing one can't draw it.
- **Copy** has one path, `useCopy`: "Copied" shows on the control and is announced; when the browser can't copy, the same button saves the file.
- **Undo** is a control in the mogi's toolbar group ([placement and lifetime](experience.md#controls)), built from existing primitives.
- **Empty states** explain only the first step.

## Score table

`ScoreMatrix` (`components/ui/score-matrix.tsx`) owns the table's geometry; the exported PNG (`tablePng`, `lib/mogi/exports.ts`) reproduces the wide presentation, checked by `tests/table-image.spec.ts`. Body rows are below the 44 pt touch minimum because they are static; the header's race buttons are interactive and meet it. The header is one line at the top: the column labels level with the race numbers, track symbols below the numbers, so the table's first ink sits the title gap below its section title, as a list's first row does. The pinned columns end in a divider and a short shadow over the races; the shadow shows only while the races are scrolled under them, fading in over the first 16px of horizontal scroll, and stays hidden where scroll timelines are unsupported. The exported PNG has no shadow.
